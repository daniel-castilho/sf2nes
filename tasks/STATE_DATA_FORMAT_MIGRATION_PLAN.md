# Migration plan — state and frame authoring format (Phase 2)

**Status:** PROPOSED (part of format decision; awaits Maintainer approval)  
**Origin:** `tasks/PHASE_2_STATE_DATA_FORMAT_SPEC.md` (Phase 2)  
**Type:** future implementation planning document — does not authorize implementation, build, test, or migration  
**Prerequisites confirmed:** Phase 0 and Phase 1 completed

---

## 1. Objective

Draw future implementation and gradual adoption steps for the declarative state/frame format, without altering the current flow nor putting existing data at risk. This is a future work plan; no action listed below is authorized for execution now.

---

## 2. Assumptions

- Format decision (external declarative format, syntax to define) was approved by the Maintainer (Gate C).
- `annotations/sf2ne.ann` remains the source of annotations, symbols, and disassembly corrections.
- `src/` continues generated by `make gen`; not edited manually.
- The build consumes artifacts foreseen by the new flow, without manual editing of generated files.
- Current Ryu data are the reference set for coverage verification; Ken and other characters are not added in this phase.

## 4. Future implementation steps (gradual plan)

### Step A — Specify and approve (Phase 2, completed with these documents)
- Define syntax (TOML/YAML/JSON), schema, and validation rules.
- Maintainer approves canonical source (Gate C).

### Step B — Implement conversion tool (not started)
- Create declarative format parser.
- Implement assembly generation equivalent to current records (7-byte header, 14/16-byte frame).
- Implement validation: known conditions, duration 1–100, resolved pointers, well-formed loop, zero/null/absent/end distinction.
- Implement diagnostics with file, record, field, and invalid reference.

### Step C — Integrate into generation flow (not started)
- Insert declarative source reading stage between `disasm.py` and `ca65` in `make gen`.
- Ensure `make gen` does not destroy nor ignore new authoring data.
- Keep `annotations/sf2ne.ann` as independent annotation source.

### Step D — Validate against current Ryu data (not started)
- Serialize current Ryu states/frames into the new format.
- Generate assembly from it and compare with currently generated assembly (structural equivalence, no semantic difference).
- Verify orphan records, unknown values, and sentinels.

### Step E — Gradual adoption (not started)
- Adopt format for a representative subset (e.g., one Ryu state) before expanding.
- Keep remaining data in existing generated assembly format.
- Rollback at any time: turn off tool and continue with generated assembly.

---

## 5. Safeguards for `make gen`

- `make gen` must not overwrite the declarative authoring source.
- `make gen` must not silently ignore new authoring data.
- If conflict between declarative source and existing annotations, the future tool must report, not silently choose.
- Assembly generated from declarative source must be byte-identical to current assembly (structural equivalence) before any broad adoption.

---

## 6. Rollback

- Deactivate conversion tool in `make gen` (return to direct `disasm.py` → `ca65` flow).
- Continue using `src/*.s` generated by last successful execution before adoption.
- Declarative source remains as source file, but is not consumed until reactivated.
- No data is lost: previous generated assembly remains available.

---

## 7. Future verification criteria (not executed now)

| Criterion | How to verify (future, with authorization) |
|-----------|--------------------------------------------|
| Structural equivalence | Generate assembly from new format and compare byte-by-byte with current Ryu assembly |
| Field coverage | All `docs/FORMATS.md` fields have schema representation |
| Orphan records | Unreachable records are present in new format |
| Unknown values | Fields with uncertain meaning use raw integer + comment |
| Sentinels | End of state, end of list, and loop are correctly represented |
| Determinism | Same input produces ordered, identical assembly in repeated executions |
| Diagnostics | Errors point to file, record, field, and invalid reference |

---

## 8. Risks and mitigations

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| New tool adds maintenance complexity | Medium | Medium | Keep tool minimal; document parser and generator |
| `make gen` overwrites authoring data | Low | High | Explicit safeguard in integration stage (Step C) |
| Orphan records not mapped by schema | Medium | Low | Treat as documented exception; do not normalize |
| Semantic difference in conversion | Low | High | Structural equivalence verification (Step D) before broad adoption |
| External library dependency | Low | Low | Use Python stdlib (`tomllib`, `json`) whenever possible |
